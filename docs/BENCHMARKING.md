# FlashCache-KV Benchmarking Methodology

## 1. Experimental Objectives

The goal of FlashCache-KV benchmarking is to measure empirical memory savings, compression latency, and inference retrieval quality across distinct KV-cache compaction strategies under identical hardware and precision constraints.

---

## 2. Evaluation Baselines

1. **Full BF16 KV Cache (Baseline A)**:
   - Preserves all historical tokens in full 16-bit precision without eviction or quantization.
   - Represents the upper bound for retrieval quality and memory consumption ($1.0\times$ compression).
2. **StreamingLLM Eviction (Baseline B)**:
   - Retains $N_{\text{sink}}$ initial tokens and the most recent $N_{\text{local}}$ tokens; intermediate tokens are completely dropped.
   - Represents the existing reference approach from prior work.
3. **ChunkKV Without Compression (Baseline C)**:
   - Partitions tokens into chunks, applies adaptive budgeting and importance ranking, but keeps retained chunks in BF16 precision.
4. **ChunkKV with Compressed Historical Blocks (Approach D)**:
   - Partitions tokens into chunks, ranks them, and quantizes historical chunks to 4-bit/2-bit precision.
5. **Complete FlashCache-KV Pipeline (Approach E)**:
   - Complete 5-stage pipeline featuring asynchronous compression, adaptive head budgeting, sink/recent protection, and thread-safe memory reclamation.

---

## 3. Metrics and Mathematical Formulas

### Memory Reduction:
$$\text{Memory Reduction (\%)} = \left( \frac{\text{Original KV Memory} - \text{Compacted KV Memory}}{\text{Original KV Memory}} \right) \times 100$$

### Compression Ratio:
$$\text{Compression Ratio} = \frac{\text{Original KV Memory}}{\text{Compacted KV Memory}}$$

### Latency Profiles:
- **TTFT (Time To First Token)**: Latency from prompt ingestion to the generation of the initial token (ms).
- **Inter-Token Latency (ITL)**: Time per autoregressive decoding step (ms/token).
- **Compression Overhead**: Execution time incurred by background quantization and packing routines (ms/chunk).
- **Dequantization Overhead**: Execution time incurred when reconstructing BF16 views for attention (ms/chunk).

---

## 4. Hardware and Environment Reporting Standards

Every benchmark report generated by FlashCache-KV records:
- Host Operating System and architecture
- Python version and PyTorch build version
- CUDA device name, compute capability, and total VRAM (or CPU model and core count)
- Memory measurements distinguishing:
  - *Allocated PyTorch Memory*
  - *Reserved PyTorch Memory*
  - *Exact Physical KV-Cache Bytes* (sum of active tensor buffers and metadata)
